# 前端卡顿排查与优化建议（非渲染引擎）

## 1. 范围与结论

本文只分析 Cesium/Mars3D 渲染引擎之外的前端问题，覆盖：

- Vue 响应式与组件调度
- 主线程计算
- 网络请求与任务轮询
- 数据解析与内存
- 本地存储
- 组件生命周期
- DOM 事件与列表渲染
- 构建体积与首屏加载
- PWA 缓存

不修改业务代码，也不把地图渲染循环作为本文的主要分析对象。

### 核心判断

当前卡顿很可能是多个因素叠加造成的：

1. 专题工作台承担了过多数据处理和 UI 状态管理。
2. 大量计算、序列化、Canvas 像素处理都在主线程执行。
3. 多组 `watch`、轮询和异步请求可能形成级联更新或请求重叠。
4. 大数据、GeoJSON、栅格和导出任务缺少 Worker 或分片处理。
5. 重量级依赖存在提前加载和全局注册问题。

## 2. 一级问题：最可能直接导致卡顿

### 2.1 专题工作台过度集中

文件：

`src/widgets/basic/thematic-workbench/index.vue`

该文件约 39 万字节，同时包含分析、图表、栅格、地震数据、模板、导出、历史记录和地图联动逻辑。

影响：

- 响应式依赖过多
- 页面初始化执行量集中
- 任意状态变化可能触发大范围更新
- 问题难以定位

建议：拆分功能模块；数据处理、图像分析和导出放入 Worker；图表和分析模块按需加载。

### 2.2 `isDirty` 全量序列化草稿

证据：`index.vue:3299`

```ts
const isDirty = computed(() =>
  JSON.stringify(snapshotDraft()) !== savedDraftJson.value
)
```

每次相关状态变化都会构造完整快照、序列化大对象并生成新字符串。

建议：使用修改计数、版本号或字段级 dirty 状态；只在保存或离开页面时生成完整快照。

### 2.3 大量 JSON 深拷贝

项目多个专题模块使用：

```ts
JSON.parse(JSON.stringify(value))
```

影响：CPU 开销、临时对象和垃圾回收压力增加，并可能丢失非 JSON 类型。

建议：只复制变更字段；大对象使用结构化克隆或不可变 patch；避免重复复制 GeoJSON 和模板数据。

### 2.4 栅格像素处理阻塞主线程

证据：`DisplaySettings.vue:186`

```ts
pixelValues = Array.from({ length: canvas.width * canvas.height }, ...)
```

同时存在 `getImageData`、`ImageData`、`drawImage`、`putImageData`、`toDataURL` 等操作。

建议：使用 Web Worker + OffscreenCanvas；使用 TypedArray；预览使用低分辨率，导出时再处理原图。

### 2.5 视频/GIF/PDF 导出占用主线程

文件：`src/widgets/basic/thematic-workbench/export-media.ts`

导出过程中会循环绘制 Canvas、创建 `VideoFrame`、读取像素并编码。持续导出时页面会明显失去响应。

建议：Worker 编码；分帧处理；限制导出分辨率和帧率；导出期间减少无关响应式更新。

## 3. 二级问题：调度与响应式链路

### 3.1 大量 watch 可能形成级联更新

文件：`thematic-workbench/index.vue:3301-3400`

监听对象包括透明度、面板、图表、地震点、分析模式、符号类型和时间范围。

风险链路：

```text
状态变化 → watch A → 地图/图表更新 → 响应式状态变化 → watch B → 重复重绘
```

建议：合并同类 watch；使用统一调度器；输入过程 debounce；避免 watch 内修改自身依赖。

### 3.2 大对象进入深层响应式

GeoJSON、模板、栅格元数据和图表数据如果使用深层 `reactive` 或 `deep watch`，会产生大量代理和依赖。

建议：大数据使用 `shallowRef` 或 `markRaw`；只把 UI 状态放入响应式系统。

### 3.3 图表实例重复初始化风险

证据：`index.vue:6430`

```ts
instance = echarts.init(el)
```

需要审计同一个 DOM 是否重复初始化、面板关闭时是否销毁、组件卸载时实例数量是否归零。

建议：建立 DOM 到实例的一一映射；初始化前复用或 dispose；组件卸载时销毁全部实例。

### 3.4 模板编辑器存在异步等待循环

证据：`index.vue:4030`

```ts
while (templateMapEditorRef.value?.isRendering()) {
  await new Promise(resolve => setTimeout(resolve, 50))
}
```

虽然有 `await`，但多个调用可能同时等待，旧任务也可能继续运行。

建议：增加任务 ID；新任务取消旧任务；使用单一任务队列。

## 4. 网络请求与任务轮询

### 4.1 `setInterval(async ...)` 可能产生请求重叠

项目中多个任务模块使用固定间隔轮询。如果接口响应时间超过间隔，下一个请求会在上一个请求完成前发出。

建议：改为“请求完成后再安排下一次”；增加 AbortController；页面隐藏时暂停；同一 job 去重。

### 4.2 轮询可能重复启动

重点检查：

- `src/widgets/eoapi-workbench/components/ThematicJobs.vue`
- `src/widgets/basic/dataset-repository/components/ThematicJobs.vue`
- `mars-map.vue` 中的异常识别任务

需要确认组件反复打开关闭后，旧定时器和请求是否全部停止。

### 4.3 STAC 分页上限较高

文件：`src/widgets/basic/dataset-repository/services/eoapi-datasets.ts`

存在最多 200 页或 400 页的连续拉取逻辑。

风险：全量数据累积到内存，列表一次性渲染，后端异常时请求时间过长。

建议：默认分页；服务端过滤；列表虚拟滚动；对 `nextUrl` 做去重和循环检测。

### 4.4 并发请求缺少统一限流

行政区解析、模板预览、封面缓存、分片上传等模块都可能并发发起请求。

建议：建立请求并发池、优先级和取消机制；页面不可见时取消低优先级任务。

### 4.5 接口超时偏长

部分分析接口统一使用 60 秒超时。

风险：失败请求长期占用 loading 状态，用户重复操作后形成重复请求。

建议：按接口设置超时；请求去重；支持主动取消；禁止重复提交。

## 5. 数据解析与内存

### 5.1 大文件 JSON/GeoJSON 在主线程解析

典型形式：

```ts
JSON.parse(await file.text())
```

涉及地震数据、GeoJSON、模板和任务结果。

建议：Worker 解析；流式处理；分批插入；只保留当前视口或筛选结果。

### 5.2 几何遍历可能出现 O(n²)

点面判断、bbox 计算、Feature 遍历和逐图形构造可能形成多重循环。

建议：预计算 bbox；建立空间索引；缓存几何分析结果；限制采样点和 Feature 数量。

### 5.3 数据复制链过长

当前数据可能经过：

```text
Response → JSON → 业务对象 → reactive → 图表数据 → 地图对象 → 导出对象
```

每个阶段都可能复制和转换。

建议：保留原始数据引用；只构造轻量索引；原始 GeoJSON 不进入深层响应式。

### 5.4 Undo 栈占用较多内存

`DbtStandardEditor.vue` 的撤销栈允许保存多份大状态。

建议：保存 patch 而不是完整快照；复用大字段引用；限制撤销总内存。

## 6. 本地存储与上传

### 6.1 分片上传频繁写 localStorage

证据：`eoapi-artifacts.ts:95`

每个分片完成后可能序列化并写入完整上传状态。

`localStorage` 是同步 API，会阻塞主线程。

建议：改用 IndexedDB；合并或节流写入；只存必要字段。

### 6.2 上传并发为 5

证据：`eoapi-artifacts.ts:30`

```ts
const MAX_UPLOAD_CONCURRENCY = 5
```

上传期间会同时进行分片读取、网络请求、状态更新和持久化。

建议：根据设备和网络动态调整并发；进度更新节流；状态写入异步化。

### 6.3 UI 状态持久化可能过于频繁

如果 watch 直接触发 `localStorage.setItem(JSON.stringify(...))`，输入、拖动和调整面板时会产生同步阻塞。

建议：输入停止后保存；统一持久化队列；只保存差异字段。

## 7. 生命周期与内存泄漏

### 7.1 异步任务可能回写已卸载组件

重点对象：fetch、图片解码、Canvas 处理、任务轮询、模板加载和图表渲染。

风险：组件销毁后仍更新状态、创建实例、写缓存或修改地图。

建议：每个组件维护 AbortController；卸载时取消请求；使用 request token 检查任务是否仍有效。

### 7.2 全局事件监听需要审计

项目存在大量：

- `window/document.addEventListener`
- `mousemove/pointermove`
- `mouseup/pointerup`
- `keydown`
- `scroll`
- 自定义事件

需要确认 add/remove 使用同一函数引用和同一 capture 配置，避免组件反复打开后监听器累积。

### 7.3 Blob URL 和临时资源清理

导出、预览和图片处理会创建 Blob URL。需要确认所有 `URL.createObjectURL` 都在任务结束或组件卸载时调用 `URL.revokeObjectURL`。

## 8. DOM 与 UI 层

### 8.1 大列表缺少虚拟滚动风险

重点检查数据集、任务、图层、模板、统计结果和图表列表。

一次性渲染大量项目会增加 Vue vnode、DOM、样式计算和事件绑定成本。

建议：虚拟列表、分页、折叠非当前区域、延迟加载。

### 8.2 高频拖动和缩放事件需要统一节流

拖动、resize、scroll、pointermove 过程中如果同时更新布局、响应式状态、Canvas、图表和地图，会造成输入掉帧。

建议：统一用 `requestAnimationFrame` 调度；拖动期间只更新轻量状态；结束后再持久化。

## 9. 构建与首屏加载

### 9.1 重量级依赖可能提前加载

依赖包括：

- ECharts / ECharts GL
- XLSX
- Three
- JSZip
- jsPDF
- GIF 编码
- SHP 解析
- 多个 Mars3D 插件

`mars-map.vue` 顶部直接导入 ECharts 和 XLSX，地图组件加载时可能一并加载这些能力。

建议：按功能动态导入；分析、导入、导出和制图模块独立异步 chunk。

### 9.2 Mars3D 插件全局注册

`src/components/mars-work/expand/index.js` 全局注册了空间、热力图、ECharts、MapV 等插件。

建议：按页面或功能动态注册；演示功能与生产功能分离。

### 9.3 生产环境保留 console

`vite.config.ts` 中：

```ts
drop_console: false
```

高频日志会产生字符串格式化、控制台 I/O 和大对象打印成本。

建议：生产环境移除 debug 日志；保留必要的 error/warn；使用可配置 logger。

### 9.4 需要检查真实首屏执行量

应通过构建分析确认：

- 首屏 JS 总大小
- 首屏同步执行时间
- 最大同步 eval 时间
- ECharts/XLSX/PDF/GIF 是否被提前加载
- 是否存在重复依赖

## 10. PWA 与缓存

Service Worker 配置了较大的缓存上限：

- Mars3D 资源最多 500 条
- 地形最多 200 条
- 高德、天地图瓦片各最多 1000 条
- 图片最多 500 条

可能带来缓存写入、磁盘占用和后台网络刷新压力。

高德、天地图使用 `StaleWhileRevalidate`，地图操作频繁时可能持续发起后台刷新请求。

建议：限制缓存规模；区分静态资源和业务数据；确认缓存更新策略不会造成重复请求。

## 11. 数据层架构优化方向

当前前端承担了大量：

- 行政区识别
- 点面判断
- 栅格像素分析
- 地震统计
- 分级分类
- 图表聚合
- 数据导出

建议将适合后端完成的聚合、统计、几何分析和数据裁剪下沉到服务端，前端只处理当前视口、当前筛选结果和交互状态。

同时应减少接口返回字段，增加：

- 服务端分页
- bbox/空间过滤
- 字段裁剪
- 几何简化
- 服务端聚合

## 12. 推荐验证顺序

1. Chrome Performance 录制卡顿过程，重点查 `JSON.stringify`、`getImageData`、图表重绘和数据解析。
2. Chrome Memory 观察专题工作台反复打开关闭后 JS Heap 是否持续增长。
3. Network 检查同一个 job、模板、GeoJSON 是否重复请求。
4. Vue Devtools 检查一次输入触发多少组件更新。
5. 构建分析确认首屏是否提前加载 XLSX、ECharts、PDF、GIF 等库。
6. 检查 `setInterval(async ...)` 是否发生请求重叠。
7. 检查组件卸载后轮询、事件监听、图表实例和 Blob URL 是否清理。

## 13. 优先级清单

### P0：先验证

1. 去掉 `isDirty` 的全量 JSON 序列化比较。
2. 将栅格像素处理移入 Worker。
3. 将视频/GIF/PDF 导出移出主线程。
4. 审计并合并专题工作台 watch 链。
5. 检查轮询是否重复启动和请求重叠。

### P1：随后处理

1. 大数据使用 `shallowRef/markRaw`。
2. 大文件 JSON/GeoJSON 放入 Worker 解码。
3. 上传状态从频繁 localStorage 改为节流 IndexedDB。
4. 图表实例统一管理和销毁。
5. 数据列表增加虚拟滚动或分页。

### P2：构建和架构优化

1. ECharts、XLSX、PDF、GIF、SHP 改为动态加载。
2. Mars3D 插件按功能动态注册。
3. 生产环境移除普通 console。
4. 建立统一请求缓存、去重和并发池。
5. 将大数据统计和几何分析下沉后端。

## 14. 最终判断

排除渲染引擎后，最值得优先怀疑的是：

1. 专题工作台主线程计算过重。
2. `JSON.stringify` 和深拷贝导致 CPU、内存和 GC 压力。
3. 栅格、GeoJSON 和导出任务没有 Worker 化。
4. watch、轮询和异步请求存在重复或级联执行。
5. 重量级依赖和插件提前加载造成首屏执行过重。

这些问题应先通过 Performance、Memory、Network 和 Vue Devtools 采样确认，再按 P0、P1、P2 顺序处理。
