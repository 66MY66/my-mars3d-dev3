# 成果删除功能排查与修复方案

## 1. 问题现象

- 页面位置：`Mars3D -> 我的仓库`
- 用户操作：点击成果卡片或详情页中的“删除”，确认后页面提示“删除失败”
- 结果表现：卡片仍保留在列表中，成果并未删除

## 2. 调查范围

### 2.1 前端交互与服务层

- `src/widgets/basic/my-repository/index.vue`
- `src/widgets/basic/dataset-repository/services/eoapi-datasets.ts`
- `src/widgets/basic/dataset-repository/services/eoapi-client.ts`

### 2.2 后端接口

- `eoAPI/dockerfiles/datasets_api/app.py`

## 3. 浏览器调试证据

### 3.1 控制台

- 删除流程没有出现前端运行时异常
- 现存 warning 主要为 WebGL `ReadPixels` 性能告警，与删除失败无直接因果关系

### 3.2 网络面板

- 修复前：
  - 进入“我的仓库”后只有 `GET /api/eoapi/datasets`
  - 确认删除后没有任何 `DELETE /api/eoapi/datasets/{id}` 请求发出
- 修复后：
  - 正常删除场景可观测到 `DELETE /api/eoapi/datasets/{id}`，响应 `200`
  - 模拟服务端异常时，`DELETE /api/eoapi/datasets/{id}` 响应 `500`

### 3.3 元素与事件绑定

- 删除按钮、确认弹窗、确认按钮的 DOM 渲染和事件绑定均正常
- 删除失败并非“按钮未绑定”或“弹窗未触发”，而是删除确认后调用链走错

## 4. 根因分析

### 4.1 前端删除逻辑只支持本地成果

`my-repository/index.vue` 中删除确认最终调用：

- `remove({ datasetId })`
- 内部固定执行 `deleteLocalManifest(datasetId)`

而 `deleteLocalManifest()` 只接受 `local_` 前缀的数据集：

- 本地数据：可删
- 远端数据：直接返回 `false`

因此页面虽然把远端成果也展示在“我的仓库”里，但删除逻辑始终按“本地成果”处理，导致远端成果永远删不掉。

### 4.2 后端缺少数据集删除接口

`datasets-api` 原先只提供：

- `DELETE /artifacts/{artifact_id}`

并没有提供：

- `DELETE /datasets/{dataset_id}`

因此即使前端想调用远端删除，也没有对应能力承接。

### 4.3 状态权限判断依赖前端本地缓存，不等于服务端真实状态

“审核中/已发布/私有”状态此前主要来自前端本地 `publish-status` 存储，不能反映服务端真实 `publish_status`。

这会带来两个问题：

- 服务端已审核中的数据集，前端仍可能把它当作“私有”
- 删除权限判断与服务端状态不一致

## 5. 修复路径

### 5.1 后端能力补齐

新增 `DELETE /datasets/{dataset_id}`：

- 校验数据集存在
- 限制仅 `private` 状态允许删除
- 同步删除：
  - `eoapi_datasets`
  - `eoapi_dataset_revisions`
  - `eoapi_artifacts`
  - `eoapi_favorites`
  - `eoapi_metric_events`
- 调用 `pgstac.delete_collection()` 清理 STAC collection / item 索引
- 清理本地附件文件

### 5.2 前端服务层补齐远端删除调用

在 `eoapi-datasets.ts` 新增 `deleteDataset()`：

- `local_` 数据集继续走本地删除
- 远端数据集调用 `DELETE /api/eoapi/datasets/{id}`

### 5.3 前端页面交互优化

在 `my-repository/index.vue` 中：

- 删除确认改为异步执行
- 删除中按钮显示 loading，避免重复提交
- 删除成功后即时从列表移除
- 删除失败时显示后端返回的明确原因
- 审核中/已发布数据集禁用“删除”按钮

### 5.4 错误提示链路增强

在 `eoapi-client.ts` 中兼容 FastAPI 标准错误体：

- 优先读取 `detail`
- 其次读取 `message`
- 最后回退到 Axios 默认错误文本

这样服务端 `409/500` 的错误原因可以被页面原样提示。

## 6. 验证结果

### 6.1 正常场景

- 创建远端数据集
- 在“我的仓库”搜索并点击删除
- 观测到：
  - `DELETE /api/eoapi/datasets/{id}` -> `200`
  - 页面提示“已删除”
  - 列表卡片消失
  - `stac-fastapi /collections/{id}` 返回 `404`

### 6.2 状态受限场景

- 创建数据集并提交共享，使其进入 `reviewing`
- 页面展示状态“审核中”
- 删除按钮禁用
- API 直接调用删除时返回 `409: dataset must be private before deletion`

### 6.3 服务端错误场景

- 浏览器层模拟 `DELETE /api/eoapi/datasets/{id}` 返回 `500`
- 页面提示“模拟服务端删除失败”
- 卡片仍保留，不会误删

## 7. 结论

本次“成果删不掉”的根因是前后端双侧缺口叠加：

- 前端误把远端成果当成本地成果删除
- 后端未提供远端数据集删除接口

修复后，成果删除链路已具备：

- 正常删除
- 状态型权限阻断
- 服务端异常提示
- STAC 索引同步清理

当前删除相关页面交互已符合预期，可进入后续提交流程。
