# 整体布局联调与框架标准化（执行方案）

## 目标
- 布局组装：整合 AI 侧边栏、地图底座、图层树为“一主多从”布局，面板行为一致（拖拽/置顶/互斥/记忆）。
- 主题系统：建立全局 CSS 变量体系，实现深/浅色切换与组件主题一致性。
- 状态管理：基于 Pinia 实现组件间通信与互斥逻辑，统一面板开关与跨组件事件。
- 二级菜单重构：梳理左侧/顶部二级菜单结构与路由/Widget 映射，按业务场景组织入口。

## 范围边界（4/10 前 MVP）
- 必须：布局容器与面板层级规范、主题切换闭环、Pinia 互斥与通信骨架、二级菜单结构重排（不做权限全量）。
- 可选：二级菜单的权限/AB 测试/可配置化下发。

## 任务拆解

### 1）布局组装（一主多从）
- **容器层级**
  - 主容器：地图
  - 从容器：右侧工具面板（底图/图层树/算子库/告警/异常识别等）
  - 顶部：状态栏/模块导航
- **面板统一规范**
  - 标题栏统一：`headerRight` 插槽 + 关闭按钮位置一致
  - 行为统一：拖拽、点击置顶、位置/尺寸记忆
  - 互斥组：右侧工具面板默认互斥（底图/图层树/算子库）
- **验收**
  - 多面板同时打开不乱层级；地图仍可操作；互斥规则生效

### 2）主题系统（CSS 变量 + 深浅色）
- **Token 定义**
  - `--bg/--surface/--text/--text-secondary/--border/--accent/--hover/--shadow/--overlay`
  - 组件禁止硬编码颜色，统一使用 token
- **切换机制**
  - Pinia 保存 themeMode，localStorage 记忆
  - 提供命令/按钮触发切换
- **验收**
  - 切换主题不刷新；核心面板与弹窗一致变色

### 3）Pinia 状态管理（通信与互斥）
- **uiStore**
  - `panels`: { layers, basemap, operators, alerts, identify, ai }
  - `activePanel`: string | null
  - `togglePanel(name, { group })`：同组互斥
- **mapIntentStore（意图驱动）**
  - `dispatch({ type, payload })`：`refreshLayers/setBasemap/toggleTerrain/flyTo`
  - 地图组件订阅并执行，避免组件互相直接依赖
- **验收**
  - 从任意入口打开面板遵守互斥；跨组件动作通过 intent 完成

### 4）二级菜单重构（业务入口梳理）
- **目标**
  - 菜单按业务场景归类，避免入口分散与重复
  - 二级菜单项映射到：Widget 打开 / 路由跳转 / 组合动作（打开面板+切图层组合）
- **实施步骤**
  - 盘点当前二级菜单项：入口、文案、绑定动作、依赖的图层/底图/Widget
  - 形成业务场景 → 菜单分组 → 菜单项清单
  - 将菜单配置化（建议 `src/config/menu.json`），由 Pinia 驱动渲染
  - 为每个菜单项定义 action schema：`{ type: 'widget'|'route'|'preset', payload }`
- **验收**
  - 二级菜单结构符合业务场景；点击后动作正确；可扩展新增场景

## 与图层组合的联动
- 业务场景梳理成果落到 `src/config/layer-presets.json`
- 二级菜单可直接触发 preset：切换底图 + 开关图层组合 + 打开必要面板

## 默认视角调整（配套）
- 将地图默认视角调整到“中国地震科学实验场”区域（97.5°–105.5°E，21°–32°N），便于业务默认展示与验收一致性。
