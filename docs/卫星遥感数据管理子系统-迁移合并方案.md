## 摘要（一页看懂）

### 做了什么

将项目一「卫星遥感数据管理」的 5 个业务页面（资源池 / 元数据 / 目录 / 查询 / 共享），从 Vue2 + ant-design-vue 1.7 重写为 Vue3 + ant-design-vue 4.2.6，接入项目二，并保留顶部导航栏、新增左侧 5 项二级菜单。

### 关键数字

| 指标 | 数值 |
|---|---|
| 新增文件 | 6 个（全部集中在 `src/pages/satellite/`，可整体删除） |
| 修改文件 | 3 个（共 4 处接线，git 可完整回滚） |
| 代码改造点 | 约 380 处（Vue2→Vue3 语法 + 全局方法去依赖） |
| ESLint 校验 | 通过，零告警 |
| 回滚耗时 | 约 30 秒（2 条命令） |

### 三个必须如实说明的事实

1. **界面完成度约 95%**，但**交互完成度约 30%** —— 查询、筛选、排序、导出、分页在原项目中就是“假的”。
2. **图表完成度为 0%，但这不是迁移造成的** —— 原项目 5 个页面**本来就没有任何图表**（无 echarts/viser/chart 组件），只有 `a-statistic` 数字卡和 `a-progress` 进度条。
3. **项目一后端是内存 Mock**，数据不落库、筛选无效、导入必崩、仓库内无建表脚本。接入它的接口没有实际价值。

# 第一章 为什么合并（原因与目的）

## 1.1 两个项目的现状对比

| 维度 | 项目一 `bohr_brain` | 项目二 `my-mars3d-dev` |
|---|---|---|
| 定位 | 地震数据管理子系统（JeecgBoot 低代码平台） | 地震科学试验场卫星遥感软件（Mars3D 三维 GIS） |
| 前端技术栈 | Vue 2.6 + ant-design-vue 1.7 + vue-cli 3 / webpack 4 | Vue 3.5 + ant-design-vue 4.2.6 + Vite 7 + TypeScript |
| 后端技术栈 | Spring Boot 2.7.10 + JDK 1.8 + MySQL + Redis | 无（纯前端 + 外部 eoAPI 服务） |
| 路由模式 | history | hash |
| 状态管理 | Vuex 3 | Pinia 3 + Vuex 4 |
| 强项 | 业务表单、表格、权限体系成熟 | 三维可视化、真实遥感数据通道（eoAPI / STAC / TiTiler） |
| 弱项 | 无三维能力；业务数据全部为 Mock | 缺少「数据管理」类业务界面 |

## 1.2 合并的三个动因

### 动因一：项目二的业务闭环缺失

项目二顶部导航栏有【数据管理】按钮，但**该按钮是空按钮** —— 点击无任何反应。

代码证据（`src/shell/components/TopModulesDropdown.vue`）：

```ts
function onModuleClick(module: ModuleItem) {
  activeModuleId.value = module.id
  localStorage.setItem(ACTIVE_MODULE_STORAGE_KEY, module.id)

  if (module.id === "visualization") { ... }
  if (module.id === "loss-assessment") { ... }
  if (module.id !== "anomaly-monitoring") {
    return          // ← data-management 落入此分支，直接返回
  }
  disableAll()
  activate({ name: "manage-layers", ... })
}
```

结论：**用户能看数据，不能管数据。**

### 动因二：项目一的卫星模块「有界面、无数据」

- 5 个页面 UI 完整，但数据 100% 硬编码在 `data()` 中；
- 后端 5 套 CRUD 是 `ConcurrentHashMap` 内存实现，重启即重置；
- 前后端数据条数与内容**互不一致**（详见 5.4），证明从未联调。

结论：**它是可复用的 UI 资产，不是可用的系统。**

### 动因三：避免重复建设

项目二已有 `dataset-repository`（约 90 个文件，含 135 KB 的 `DatasetDetail.vue`、77 KB 的 `eoapi-datasets.ts`）在做数据集管理；项目一有 5 个业务化界面。

合并思路：**让业务视图复用底层能力**，而非两套各建一遍。

## 1.3 合并目标

> 让项目二具备【卫星遥感数据管理】的完整业务入口：界面 1:1 继承项目一，数据源后续切换为项目二已有的真实遥感服务。

**本次范围明确收敛为：界面不丢失、可运行、可回滚。不承担原项目功能补全。**

## 1.4 明确的非目标（Non-Goals）

- ❌ 不追求像素级复刻 ant-design-vue 1.7 的观感（antdv 4 默认外观即作为基线）
- ❌ 不接入项目一的 Java 后端
- ❌ 不在本次补齐查询/筛选/导出等缺失功能
- ❌ 不改造项目二现有的 `dataset-repository`

## 3.3 关键设计决策

### 决策 1：复用 `ShellLayout`，不自绘顶部栏

初版方案曾自绘顶部栏，已修正。理由：

- 顶部栏含 logo、品牌区、状态栏、通知、设置、用户菜单共 6 个组件
- 自绘会导致后续顶部栏改动需同步两处，易不一致
- 采用 `#sidebar` 具名插槽，默认内容仍为原 `Sidebar`，对地图页零影响

```vue
<!-- ShellLayout.vue 改动 -->
<div class="shell" :style="shellStyle">
  <slot name="sidebar">
    <Sidebar :collapsed="isSidebarIconOnly" @toggle="toggleSidebar" />
  </slot>
  ...
</div>
```

### 决策 2：三个全局方法改为局部 import

项目二的 `MarsUIInstall` 将 `$message` **覆盖**为另一个签名：

```ts
// src/components/mars-ui/mars-message/index.ts
export const $message = (msg: string, type: keyof typeof message = "info") => { ... }
export default function (app: App): void {
  app.config.globalProperties.$message = $message
}
```

因此 `this.$message.success(...)` 会抛 `TypeError`。同时 `$confirm` / `$info` 未注册（`app.use(Modal)` 只注册组件，不挂全局方法）。

**处理方式：全部改为页面内 `import { message, Modal } from "ant-design-vue"`，共 53 处。绝不修改 `mars-ui` 共享注册表。**

### 决策 3：缺失组件局部注册

`MarsUIInstall` 未注册 `Statistic` / `Descriptions` / `Badge` 三个组件（页面共使用 16 + 38 + 4 处）。处理方式：各页面 `components` 内局部注册，不动全局。

### 决策 4：颜色原样保留

页面内 `#f0f2f5` / `#1890ff` / `#8c8c8c` 等硬编码色值**原样保留**，以保证与项目一外观一致。代价：该模块不跟随项目二的深色模式。

# 第六章 接入什么（明确结论）

## 6.1 结论

> **项目一的接口，一个都不需要接入。**
> **需要接入的是「5 张表的字段模型」，作为字段映射依据，落到项目二的 eoAPI / STAC 体系上。**

## 6.2 三类资产的处理判定

| 项目一资产 | 判定 | 理由 |
|---|---|---|
| 5 套 Java 接口（`/ai2/satelliteXxx`，40 个端点） | ❌ **不接** | 内存 Mock + 筛选失效 + 无 DDL，接入等于接空壳 |
| 5 张表的**字段定义** | ✅ **要接（作为 Schema 依据）** | 唯一的业务语义资产，用于字段映射 |
| `SatelliteMenuInitListener`（718 行 / 35 按钮权限） | ❌ **不接** | 项目二菜单由前端路由 + 自绘侧栏承载，权限体系不同 |
| `BrManager*` / `GPTToken` / `ToRemoteSend` / `GateWayRouteUtils` | ❌ **不接** | 与本主题无关 |

### 表二：`satellite_data_pool`（16 字段）→ STAC 无原生对应

| 项目一字段 | 处理方式 |
|---|---|
| `id` / `poolName` | `collection.summaries` 或独立配置表 |
| `totalCapacity` / `usedCapacity` | 存储侧指标，需业务层维护 |

**结论：STAC 是检索协议，不存储检索历史，必须自建。**

### 表五：`satellite_data_share`（17 字段）→ 部分映射

| `downloadLimit` / `downloadCount` | 业务层计数 |
| `auditStatus` / `auditComment` | **需自建审核流** |
| `status` / 审计字段 | 扩展字段 |

**结论：需业务层自建授权与审核体系。**

## D.2 常见问题排查

| 现象 | 排查方向 |
|---|---|
| `Cannot find module '@/pages/satellite/...'` | `router.ts` 路径与实际磁盘不一致，实际为 `views/` 子目录 |
| `Failed to resolve component: AStatistic / ADescriptions / ABadge` | 对应页面 `components` 块遗漏局部注册 |
| `this.$refs.xxxFormRef.validate is not a function` | ref 名不一致，应为 `createFormRef` / `importFormRef` / `metadataFormRef` / `catalogFormRef` / `authFormRef` |
| 左侧栏未替换 | `ShellLayout.vue` 的 `<slot name="sidebar">` 被破坏 |
| 内容区宽度错位 | `:sidebar-width="240"` 未传递到 `shellStyle` |
| 改动后页面未变化 | PWA 缓存，需 Unregister Service Worker + 强制刷新 |
| 点击【数据管理】无反应 | 跳转分支被置于 `module.id !== "anomaly-monitoring"` 之后 |
