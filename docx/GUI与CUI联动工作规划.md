## 1. 总体概述 (Executive Summary)

本规划旨在打造一套 **GUI (图形用户界面)** 与 **CUI (对话式用户界面)** 深度融合的智能交互系统。
- **GUI** 负责直观的空间展示、复杂的工具操作与数据可视化。
- **CUI** 负责意图识别、快捷指令下达与跨模块调度。
两者通过 **统一事件总线** 和 **共享状态库** 实现无缝协同，提供"所见即所得"与"所说即所得"的双重体验。

## 2. 需求分析与协同机制 (Requirements & Synergy)

### 2.1 使用场景与互补点
| 场景 | GUI 职责 (可视化/操作) | CUI 职责 (意图/调度) | 协同机制 |
| :--- | :--- | :--- | :--- |
| **告警研判** | 展示异常点位置、热力图、工具栏面板 | 接收"查看详情"指令，播报异常摘要 | **CUI -> GUI**: 对话跳转定位<br>**GUI -> CUI**: 选中点填充对话上下文 |
| **报告生成** | 预览图表、下载 PDF 按钮 | 接收"生成四川评估报告"指令，调度多 Agent | **CUI -> GUI**: 输出 Markdown 简报卡片 |
| **时空演化** | 左右分屏对比、时间轴播放 | 接收"对比震前震后"指令，自动开启分屏 | **CUI -> GUI**: 触发分屏模式与图层加载 |

### 2.2 架构设计 (Architecture)
*   **后端服务**: 统一 API 网关 (GraphQL/REST)，同时服务于 GUI 组件与 CUI Agent。
*   **状态管理 (Pinia)**: 建立 `AppStore` (GUI状态) 与 `ChatStore` (会话上下文)。
    *   *Shared State*: `currentRegion` (当前区域), `selectedLayer` (选中图层), `timeRange` (时间范围)。
*   **事件总线 (EventBus)**:
    *   `CUI_ACTION`: CUI 发出的指令 (如 `FLY_TO`, `SPLIT_SCREEN`) -> GUI 监听执行。
    *   `GUI_EVENT`: GUI 产生的事件 (如 `MAP_CLICK`, `DRAW_END`) -> CUI 监听并生成建议。

## 4. 接口协议与规范 (Interface & Protocol)

### 4.1 接口规范
*   **CUI API**: 采用 **Server-Sent Events (SSE)** 实现流式对话。
    *   `POST /api/chat/completions`: 发送用户消息，返回流式 Markdown。
*   **GUI API**: 采用 **RESTful** 标准。
    *   `GET /api/layer/{id}`: 获取图层数据。
    *   `POST /api/analysis/verify`: 提交研判结果。

### 4.2 CUI 命令协议 (JSON Schema)
前端 CUI 解析层将自然语言转换为标准 JSON 指令，分发给 GUI 执行：
```json
{
  "action": "FLY_TO", // 动作: FLY_TO, SHOW_LAYER, SPLIT_SCREEN
  "payload": {
    "center": [103.4, 30.5],
    "zoom": 12,
    "duration": 2
  },
  "target": "map_main" // 目标组件: map_main, panel_right
}
```

### 4.3 错误码与日志
*   **GUI 错误**: 弹窗提示 (`Toast`)，并上报日志。
*   **CUI 错误**: 在对话气泡中输出友好提示 ("抱歉，我没听懂，请重试")，不阻断 GUI 操作。
